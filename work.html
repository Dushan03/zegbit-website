Finding ZB-01

SQL injection in product search

Critical · 9.8
CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H
Affected
GET https://app.example.com/search?q=
Category
OWASP A03:2021 Injection · CWE-89
Status
Fixed · verified in retest

Description

The q parameter was concatenated directly into a SQL query. Adding a quote character changed the query logic, so the application returned every row in the products table instead of matching items.

Evidence (sanitised)

GET /search?q=shoes%27+OR+%271%27%3D%271 HTTP/1.1
Host: app.example.com

HTTP/1.1 200 OK
X-Result-Count: 4812      # expected: 37

Impact

An unauthenticated attacker could read, and potentially modify, data in the shared database, including customer names, emails and order history.

Remediation

  • Use parameterised queries or the ORM query builder for every database call.
  • Validate search input against an allow-list of characters and length.
  • Run the database user with read-only rights for search queries.
  • Add SAST (e.g. Semgrep) to CI to catch string-built SQL before release.

Retest

The same request now returns the expected 37 results and the payload is treated as plain text. The query uses bound parameters. Closed.

References

  • OWASP Top 10 2021 — A03 Injection
  • OWASP Cheat Sheet — SQL Injection Prevention
  • CWE-89: Improper Neutralization of Special Elements in SQL
